## 55-14 magic-link review

56 §5.15 sets the controls for the client magic link. Checked against the code on 2026-11-02. Tests: `apps/api/src/modules/public-links/public-links.magic-link-review.test.ts`.

| Control (56 §5.15)                                                                                     | Today                                                                                                                                                                                                                                                                                           |
| ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `public_links` row of kind `magic_signin`, 256-bit token, peppered hash                                | Built: `PUBLIC_LINK_KINDS` has `magic_signin`; `PublicLinkSecrets` stores only `HMAC(pepper, token)`.                                                                                                                                                                                           |
| One-time use                                                                                           | Built when the link is issued with `maxUses: 1`: the second open returns `expired` and no projection (**SEC56-23**). Not forced: the kind does not set `maxUses` itself.                                                                                                                        |
| Second use answers like an unknown token                                                               | **Gap**: a consumed link answers 200 `{ state: 'expired' }`, an unknown one 404. Recorded as `it.todo` in the test.                                                                                                                                                                             |
| Use counted atomically                                                                                 | **Gap**: `PublicLinksRepository.recordOpen` increments `uses` without a `uses < max_uses` predicate, so two parallel first opens can both pass.                                                                                                                                                 |
| No session merge                                                                                       | Built at this seam: the outsider path takes only the token and `{ ip, userAgent }`, runs in a service context for the link's organization, and returns no principal (**SEC56-24**).                                                                                                             |
| Expiry 15 minutes                                                                                      | **Gap**: expiry is whole days (1–30, default 7); there is no minute-level expiry for `magic_signin`.                                                                                                                                                                                            |
| Audience binding (invited e-mail + client membership id)                                               | Partly: `audience_email` exists and the code is mailed only there; nothing checks it against the client membership's e-mail at issue.                                                                                                                                                           |
| Creates a normal client session; never a membership                                                    | Built (55-14): `POST /v1/public/portal-sign-in/links/:token/consume` spends the one use and starts a normal session (`SessionService.start`); it writes no membership and refuses while another session is signed in.                                                                           |
| Code fallback after three failed opens, `authentication_events` `method='magic_link'`, "Not you?" link | Built (55-14, R43 L1): `PortalSignInService` mails a 6-digit code with the next link after three failed opens in an hour; every attempt is an `authentication_events` row with action `magic_link`; "Not you?" revokes the link and mails the address. Tests: `portal-sign-in.service.test.ts`. |

Before 55-14 ships the sign-in itself, the gaps marked above close in that slice: force `maxUses = 1` and a 15-minute expiry for the kind, make `recordOpen` conditional, answer a consumed link with the flat 404, and refuse to open while another client session is present (sign out first).

## Client ceiling review

`packages/domain/src/policies/client-ceiling.ts` holds `CLIENT_CAPABILITY_ALLOWLIST`; `client-ceiling.test.ts` proves the four client roles stay inside it. `requireClientCeiling` (`apps/api/src/modules/tenancy/role-grant-ceiling.ts`) refuses a client role carrying an internal capability with 422 `client_ceiling`, and the policy simulator returns a `client_internal_capability` warning for one. The guard is exported for the custom-role and member-role write paths; wiring it into those paths is their owners' change.
