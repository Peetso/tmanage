# TManage Engineering Standard

**Status:** binding. Adopted by ADR-0008 (staged; see README §5). **Version** 1.0, 2026-11-20.
**Scope:** every design, build, review and deploy in `D:/TManage/code/tmanage`.
**Replaces:** the rule list in `ENGINEERING-RULES.md`. That file is now only a pointer, and its §8 defect classes are in §13 below.

How to read a rule row:

- **ID**: stable; cite it in briefs, ADRs and commit messages.
- **Rule**: what must be true. MUST / SHOULD are used as in RFC 2119.
- **Why / source**: refers to the source register in §1.
- **Today**: what the code does now, with `file:line` evidence from the working tree on 2026-11-20. That tree includes the uncommitted AUTHSTATE work.
- **Target**: what must be true once the rule is met.
- **Check**: the fitness function. **E** means it exists (path given). **B** means it still has to be built (spec given; the full spec is in `FITNESS-FUNCTIONS.md`).

A rule without a check is a wish. Every **B** is tracked in `FITNESS-FUNCTIONS.md`.

## 4. HTTP semantics and client conclusions (RFC 9110)

**What a client may conclude from an answer.** This table is normative. It is implemented once and every client uses it (HT-2).

| Answer                                                | RFC 9110                                                                                              | Conclusion                                                                                        | Allowed client action                                                                                       |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 2xx                                                   | §15.3                                                                                                 | answer                                                                                            | render                                                                                                      |
| 401                                                   | §15.5.2: the request "lacks valid authentication credentials"                                         | credentials missing or expired. **Not yet "signed out"**: an access cookie may be stale           | one refresh; still 401 → signed out                                                                         |
| 403                                                   | §15.5.4: understood, refused; re-authenticating "will not make a difference" for the same credentials | denied for **this** resource. The session is still valid                                          | show "no access"; **never** sign out                                                                        |
| 404                                                   | §15.5.5: no current representation, or the server will not disclose one                               | not found **or hidden** (tenant isolation answers 404)                                            | show not-found. Never infer "signed out" or "empty list"                                                    |
| 408, 429                                              | 408: RFC 9110 §15.5.9; 429: RFC 6585 (both unverified)                                                | **unknown**: try later                                                                            | retry with backoff; honour `Retry-After`                                                                    |
| 5xx, 503 + Retry-After, timeout, network error, reset | §15.6, §15.6.4, §10.2.3                                                                               | **unknown**: the server failed or is starting. **It says nothing about identity, access or data** | show "Can't reach TManage, retrying". Keep cookies. Never show the sign-in form, an empty state or "denied" |

## 5. Data, transactions, migrations (MariaDB 11.8 live, MySQL 8 local)

Isolation background: ANSI levels are defined by phenomena, and that definition misses anomalies such as lost update and write skew, which snapshot-based engines allow (S11).
