# Part documentation system

**Status:** binding, as changed by Peter on 2026-11-20: **TManage follows general standards, not a doc for every part.** The standards in `docs/architecture/` (start at `README.md`) apply to every part. A `PART.md` is optional: the 18 that exist are kept, checked (PD-1…PD-8) and must be read before their part is edited; no new ones are required, and the rollout to the remaining parts is cancelled. **Version** 1.1, 2026-11-20 (1.0 required a doc for every part). Decision record: ADR-0011 (staged; amended the same day).

This file defines:

- the **parts**;
- the **template**;
- **where** the docs live;
- **how a model is forced to read them first**;
- the **check** that keeps them true.

In short:

- **Every edit** of a repository file outside `docs/` and `.claude/` needs `docs/architecture/README.md` read once in the session (each subagent reads it itself). The edit gate (§3.3) enforces this.
- **A part with a `PART.md`**: that `PART.md` must also be read before its part is edited, and it must pass PD-1…PD-8 (§6).
- **A part without a `PART.md`** never blocks an edit and never fails `pnpm arch:parts`. There is no missing-docs baseline any more.

18 parts have a `PART.md` today (the script prints the count). §7 records the cancelled rollout.

## 3. Where docs live and how reading is forced

### 3.1 Location (docs-as-code, co-located)

| Part kind            | Doc path                                                                                                  | Loader file                                                                                                                                                                                                        |
| -------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| API module           | `apps/api/src/modules/<module>/PART.md`                                                                   | `apps/api/src/modules/<module>/CLAUDE.md` = `@PART.md`                                                                                                                                                             |
| Package              | `packages/<pkg>/PART.md`                                                                                  | `packages/<pkg>/CLAUDE.md`                                                                                                                                                                                         |
| App runtime          | `apps/server/PART.md`, `apps/worker/PART.md`, `apps/mcp-server/PART.md`, `apps/desktop/PART.md`           | same folder `CLAUDE.md`                                                                                                                                                                                            |
| Web route area       | `apps/web/src/app/<area>/PART.md` (for example `[orgSlug]/projects/`)                                     | same folder `CLAUDE.md`. Next.js treats only special files (`page`, `layout`, `route`…) as routes, so colocated `.md` files are not served (Next docs "Project structure / colocation", **verify before rollout**) |
| Design-system area   | `packages/ui/src/<area>/PART.md` (tokens, components/<Name>, a11y, styles), plus `packages/ui/vr/PART.md` | same folder `CLAUDE.md`                                                                                                                                                                                            |
| E2E, deploy, scripts | `e2e/PART.md`, `deploy/hostinger/PART.md`, `scripts/<area>/PART.md`                                       | same folder `CLAUDE.md`                                                                                                                                                                                            |

`apps/web/CLAUDE.md` already exists (`@AGENTS.md`, the Next.js agent block). It gains a second line, `@PART.md`. Nothing is removed.

**Registry:** `docs/architecture/parts.json` is generated by `part-docs-check.mjs --write-registry` from the directory rules in §3.4. Each entry gives `{ id, kind, paths[], doc, context }`. The registry is the only map from a file path to its part.

### 3.2 Background work belongs to its context

A worker job, outbox consumer or scheduled sweep is documented in the **owning module's** `PART.md`, in the section "Runtime and background work". It is not given a part of its own. Examples:

- `apps/worker/src/jobs/budget-burn-sweeper` belongs to `modules/copilot` or `projects` (owner fixed in `parts.json`);
- the `signals-sweeper` sweep in `apps/server/scheduled-sweeps.mjs` belongs to `modules/insights`.

Reason: DDD (a bounded context owns its processes; ENGINEERING-STANDARD S5) and Shopify's "owns its data" rule. `apps/worker/PART.md` and `apps/server/PART.md` document only the runtime itself: dispatcher, leases, boot, transport, gates.

### 3.3 Forcing "read first" (three layers)

| Layer              | Mechanism                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Strength                                                       | Status                                            |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- | ------------------------------------------------- |
| L1 Context         | Each part folder has a `CLAUDE.md` with `@PART.md`. Claude Code loads it on the first read, write or edit in that folder (C1, C2).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | automatic, but **after** the first touch and not enforced (C8) | to build with each part doc                       |
| L2 **Gate (hard)** | `.claude/settings.json` (project, committed) hooks, implemented in `scripts/arch/part-docs-gate.mjs`:<br/>• **PostToolUse** on `Read`: if `file_path` is `docs/architecture/README.md` or a `PART.md`, append `{session_id, agent_id, doc}` to `.claude/state/part-reads.jsonl`.<br/>• **PreToolUse** on `Edit\|Write\|MultiEdit\|NotebookEdit` and on shell write targets (`Bash\|PowerShell`): (1) any repository file needs a recorded read of `docs/architecture/README.md` for this `session_id`+`agent_id` (once per session); (2) if the file's part (via `parts.json`) **has** a `PART.md`, that one must be read too. A part without a `PART.md` adds nothing. Denial is exit 2 with the reason on stderr.<br/>• Exempt: `PART.md` and `CLAUDE.md` files, `docs/**`, `.claude/**`, files outside the repository.<br/>• Fails closed when `parts.json` or `docs/architecture/README.md` is missing or malformed. | enforced for the manager and every subagent (C6)               | built; tests in `scripts/arch/part-docs.test.mjs` |
| L3 Brief + report  | Every worker brief lists the parts it touches and says: _"Before any edit, Read each listed `PART.md` (the edit gate will refuse otherwise). Quote the rule IDs you apply from it and from the standards."_ The worker's report must contain a `Parts read:` line with the part ids and the quoted rule IDs. The manager rejects a report without it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | process; checked by `design-checklist.mjs`                     | to build (DESIGN-CHECKLIST §I)                    |

Why the record is written on Read rather than found by parsing the transcript: the hook docs give the transcript path, but lane B could not confirm which transcript a subagent's hook receives. A state file keyed by `session_id` + `agent_id` avoids depending on that. `.claude/state/` is git-ignored.

## 4. The `PART.md` template

Front-matter (YAML; fields adapted from the Backstage descriptor):

```yaml
---
part: api/identity # registry id
kind: api-module # api-module | api-common | package | ds-area | app-runtime | web-area | web-shared | ops
context: identity-and-access # VIEWS.md §4 context (Backstage "system")
owner: implementation-lead
lifecycle: production # experimental | production | deprecated
depends_on: [api/tenancy, api/audit, package/domain]
provides_api: ['/v1/sessions/*', '/v1/auth/*']
consumes_api: []
tables_owned: [users, sessions, mfa_factors]
rules: [SE-2, SE-3, AR-8, AR-9, HT-1] # IDs from the standards that apply
ux_rules: [UX-8] # UI-UX standard IDs (web/ds parts)
last_verified_commit: <sha>
last_verified_date: YYYY-MM-DD
last_verified_by: <model/name>
---
```

Required sections, with headings exactly as below (the check matches them):

| #   | Heading                                         | Diátaxis form           | arc42 link  | Must contain                                                                                                                                                           |
| --- | ----------------------------------------------- | ----------------------- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `## Purpose and bounded context`                | explanation             | §1, §3      | what the part is for, who uses it, context map relations (upstream/downstream, shared kernel)                                                                          |
| 2   | `## Domain model and invariants`                | explanation + reference | §5, §8      | entities, value objects, state machines; each **invariant** as a checkable statement with the test that proves it                                                      |
| 3   | `## Public API and contracts`                   | reference               | §3, §5      | routes (method, path, status codes per ENGINEERING-STANDARD §4), events published/consumed, exported services; contract file `e2e/contracts/api-web-shapes.ts` entries |
| 4   | `## Data: tables and migrations`                | reference               | §5, §8      | owned tables, columns that matter, unique/dedupe keys, migrations (ids), expand/contract state, retention class                                                        |
| 5   | `## Permissions and tenant rules`               | reference               | §8          | capabilities per route, tenant scope, trust zone, step-up needs; where each decision is made (single source of truth)                                                  |
| 6   | `## Runtime, background work and failure modes` | explanation             | §6, §8, §11 | jobs, consumers, sweeps owned; leases; timeouts; breaker; what happens on DB, network or third-party failure, and on two instances (stability patterns by ID)          |
| 7   | `## UX rules for its screens`                   | reference               | §8, §10     | screens and Figma node ids, persona journeys, UX-* IDs, copy keys, empty, error and unknown states. `n/a` for non-UI parts                                             |

| 10  | `## Tests and fitness checks`                   | reference               | §10         | test files (unit, db, e2e, VR), fitness functions, revert proofs                                                                                                       |

## 6. Fitness check: `scripts/arch/part-docs-check.mjs` (`pnpm arch:parts`, tests `pnpm test:arch`)

| Check | Fails when                                                                                                                                                         | Mode                                             |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| PD-1  | A part that **has** a `PART.md` has no `CLAUDE.md` importing it (`@PART.md`). A part without a `PART.md` is not checked.                                           | error (no missing-docs ratchet since 2026-11-20) |
| PD-2  | Front-matter missing or invalid (schema in the script); `part` ≠ registry id; `context` not in VIEWS §4.                                                           | error                                            |
| PD-3  | A required heading (§4) is missing or out of order; a heading has no content and no `n/a — reason`.                                                                | error                                            |
| PD-4  | A rule ID in `rules` / `ux_rules` / the text does not exist in ENGINEERING-STANDARD, UI-UX-DESIGN-STANDARD or IMPLEMENTATION-PATTERNS.                             | error                                            |
| PD-5  | **Staleness:** `git rev-list --count <last_verified_commit>..HEAD -- <part paths>` > **N = 15** (proposed), or `last_verified_commit` is not an ancestor of HEAD.  | error in `verify`; the warning threshold is N/2  |
| PD-6  | A commit changes files of a part with lifecycle `production` but not its `PART.md` and the doc is already at N/2. (Pre-commit form of PD-5, run by the committer.) | warning                                          |
| PD-7  | `PART.md` > 30,000 characters.                                                                                                                                     | error                                            |
| PD-8  | `tables_owned` disagrees with `docs/architecture/table-owners.json` (AR-7), or `provides_api` routes are missing from the route census.                            | error once AR-7 exists                           |

It runs in `pnpm verify` (script) and as `--write-registry` when directories change. It is read-only (`git rev-list` only), so it is safe under the "no git commands by lanes" rule.

## 7. Rollout: cancelled (Peter, 2026-11-20)

Version 1.0 planned a `PART.md` for every part, in three waves, held by a missing-docs baseline (`docs/architecture/baselines/parts-missing.json`) that could only shrink. Waves 0–2 were done: the gate, the check and 18 part docs (the P0 kernel plus projects, work, audit, platform, files, clients and their web areas).

On 2026-11-20 Peter changed the rule: TManage keeps **general standards**, not a doc for every part. So:

- the rollout to the remaining parts is cancelled;
- the baseline file and the P0 list are removed; a part without a `PART.md` is not an error;
- the 18 existing `PART.md` files stay, keep their checks (PD-1…PD-8) and are still read before their part is edited;
- a new `PART.md` may still be written where a part has rules the general standards do not cover. It then follows §4 and §6 like the others.

The general standards are the read path for everything else: `README.md` → `ENGINEERING-STANDARD.md`, `IMPLEMENTATION-PATTERNS.md`, `UI-UX-DESIGN-STANDARD.md`, `DESIGN-CHECKLIST.md`.
