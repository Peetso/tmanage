# Pattern — Pulse Track

**Problem it solves.** Work systems tell you a state; they rarely tell you *where you are in time*.
Pulse Track is one grammar reused for schedule, milestone, request, delivery version and client journey,
so a person learns it once.

**Grammar.** ink = confirmed history · lime = now/next (exactly one) · outlined = future or uncertain ·
dashed = unknown/unscheduled · orange edge = risk. Avatars appear only where participation matters.

**Where it appears.** HOME-01 (today), PRJ-01 (milestones), DEL-02 (governed versions), REQ-02 (request),
CL-01/CL-04 (client journey), CAL-02 (day), ON-04/ON-05 (onboarding preview).

**Where it must not appear.** It is not page chrome. If a surface has no meaningful linear story
(admin lists, docs, search), there is no track.

**Accessibility.** Ordered list equivalent, single tab stop with ← → traversal, text state on every
segment, no meaning from position alone, 300ms progress glide that reduced motion replaces with a swap.

**RTL.** Interface-flow tracks start from the right. Chart-style time axes stay LTR and are documented
per instance.
